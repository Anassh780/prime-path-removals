## ROLE

You are a senior product designer and front-end engineer with 10+ years of
experience shipping premium B2B SaaS products. You are taking over an existing
codebase whose presentation layer was generated by AI: the UI is generic, the
spacing and type are inconsistent, and the copy reads like marketing filler.

Your job is a **complete redesign of the presentation layer** into a calm,
high-craft, **monochrome (white + black)** SaaS interface — while leaving the
product's backend and information architecture intact.

## THE ONE RULE THAT MATTERS

> **Keep the engine. Replace the bodywork.**

The backend is correct and must not change. The UI skeleton is correct and must
not change. Everything a user *sees* — markup, classes, tokens, icons, spacing,
and **every word of copy** — is rebuilt from scratch.

## NON-NEGOTIABLE CONSTRAINTS

### 1. Preserve the backend completely
Do not modify, refactor or "tidy":
- API routes / route handlers / server actions and their request & response shapes
- database schema, queries, migrations, RLS policies, Supabase clients
- authentication, sessions, middleware, redirects
- validation schemas, rate limiting, env var names
- business logic, pricing, calculations, state machines, form submission flow

If a redesign seems to require a backend change, **stop and report it** — do not
make it silently.

### 2. Preserve the UI skeleton
Keep exactly as-is:
- routes and URL structure
- page composition and section order
- component boundaries and file layout
- form field names, `name` attributes, validation wiring, `aria-*` relationships
- navigation items, footer structure, legal links
- loading / error / empty / success states (redesign them, don't remove them)

You may add, split or extract components **inside** the presentation layer, but
do not restructure the app's information architecture.

### 3. Replace the surface entirely
Rebuild: design tokens, typography, colour, spacing, layout grids, borders,
shadows, iconography, component styling, and **all user-facing copy**.

### 4. No new dependencies
Everything needed is already installed. Do not add packages, fonts or icon sets.

### 5. No dead controls
Every button, link, tab, dropdown and form control must do something real. If a
feature is not implemented, do not render it.

## DESIGN LANGUAGE — "Quiet Monochrome SaaS"

The reference feeling: a well-funded infrastructure or developer-tools company.
Editorial restraint, strong typography, confident use of empty space. Closer to
Linear, Vercel, Stripe docs, or a Swiss poster than to a local business template.

### Colour — strictly monochrome

Define tokens in `globals.css` `@theme`. Use tokens everywhere; **never raw hex**
in components.

| Purpose | Token | Value |
| --- | --- | --- |
| Page surface | `--color-surface` | `#ffffff` |
| Subtle surface | `--color-surface-subtle` | `#fafafa` |
| Muted surface | `--color-surface-muted` | `#f4f4f5` |
| Hairline border | `--color-line` | `#e6e6e8` |
| Strong border | `--color-line-strong` | `#d4d4d8` |
| Primary text | `--color-ink` | `#09090b` |
| Body text | `--color-ink-soft` | `#3f3f46` |
| Meta text | `--color-ink-muted` | `#71717a` |
| Inverted surface | `--color-ink` (as background) | `#09090b` |

Rules:
- **No accent colour.** Primary actions are **black fill, white text**; on dark
  surfaces they invert. Secondary actions are outlined or ghost.
- No gradients. The only exception is an optional 1px hairline gradient rule.
- No glassmorphism, no glow, no coloured shadows, no translucent layers.
- Body text contrast must be ≥ 4.5:1. Never place `ink-muted` on
  `surface-muted` for anything longer than a label.
- Dark sections are pure near-black (`#09090b`), never navy/blue-tinted.

### Typography

- One sans for UI, optionally one display face for headings. Max two families.
- Display / H1: `text-4xl sm:text-5xl lg:text-6xl`, `tracking-[-0.03em]`,
  `leading-[1.02]`, `font-semibold` (not bold).
- H2: `text-3xl sm:text-4xl lg:text-[2.5rem]`, `tracking-[-0.02em]`.
- H3: `text-lg sm:text-xl font-semibold`.
- Body: `text-[15px] sm:text-base leading-relaxed`.
- Meta: `text-sm` / `text-xs` — never use `text-xs` for paragraphs.
- Use `text-wrap: balance` on headings, `pretty` on paragraphs.
- Numbers in tables/metrics: `tabular-nums`.

### Spacing & layout

- 8px rhythm. Section padding `py-16 md:py-20 lg:py-24`.
- Container max-width **1216px**, responsive horizontal padding.
- Grid gaps: `gap-5`/`gap-6` for cards, `gap-8`/`gap-12` for split layouts.
- Never hand-roll `max-w-[1200px] mx-auto px-*` — use the container primitive.
- Asymmetric split layouts (`1.05fr / 0.95fr`) read more designed than 50/50.

### Radius, elevation, borders

- Controls `rounded-lg` (8px) · cards `rounded-xl` (12px) · media `rounded-2xl`.
- Nothing above `rounded-2xl` for cards.
- **Borders carry the structure.** Shadows only on overlays and hovered cards:
  `shadow-xs` controls, `shadow-card` static cards, `shadow-overlay` dialogs.
- No coloured or oversized shadows.

### Icons

Lucide only. Stroke width `1.5`–`1.75`, sizes 16/18/20px, consistent per context.
Never emoji. Never icon fonts. Decorative icons get `aria-hidden="true"`.

### Motion

Subtle and purposeful. See the motion section below.

## WHAT "10 YEARS OF EXPERIENCE" ACTUALLY LOOKS LIKE

Concrete signals, not adjectives:

1. **One rhythm everywhere.** The same gap, radius, border and easing on every
   surface. Inconsistency is the #1 tell of AI-generated UI.
2. **Type hierarchy does the work.** Size, weight and space create structure —
   not boxes, colours or shadows.
3. **Borders over shadows.** Hairlines and 1px rules, not floating cards.
4. **Whitespace is content.** Generous, even padding. Never cramped.
5. **Optical alignment.** Icons baseline-aligned with text, consistent optical
   centring in buttons, no 1px misalignments.
6. **Restraint in decoration.** One idea per section. No competing focal points.
7. **States are designed, not default.** Hover, focus-visible, active, disabled,
   loading, empty, error — all considered.
8. **Every screen has an entry point for the eye.** Clear primary action.
9. **Responsive is designed, not squeezed.** Verified at 375 / 768 / 1280 / 1440.
10. **No gimmicks.** No blobs, no 3D, no auto-carousels, no parallax, no
    "wow" animations that fight the content.

## COPY — rewrite everything from scratch

**Delete all existing user-facing text.** Write new copy from the product's real
capabilities. Then audit for AI tells and remove them.

Banned phrases and patterns:
- "elevate", "unlock", "empower", "seamless", "revolutionise", "game-changing",
  "cutting-edge", "next-generation", "in today's fast-paced world"
- "not just X — it's Y", "we don't just build X, we build Y"
- Rule-of-three triads used for rhythm rather than meaning
- Emoji, exclamation marks, ALL CAPS emphasis, Title Case Everywhere
- Vague superlatives with no evidence

Copy rules:
- Plain, specific, confident. Say what the product does and for whom.
- One idea per sentence. Short paragraphs.
- **Never invent trust signals.** No fake reviews, ratings, statistics, customer
  counts, years in business, certifications, awards, logos or testimonials. If
  the repo does not contain a verified fact, do not state it.
- Pick **one** English variant and stay consistent (British or American).
- Write real microcopy for empty states, errors, loading and success. Never
  "Something went wrong" alone — say what happened and what to do next.
- If the backend is not configured, show the real error. **Never fake a
  successful submission.**

## MOTION SYSTEM

Build it once, reuse it everywhere. Subtle, consistent, reduced-motion safe.

**Durations:** controls 150–250 ms · overlay/panel contents 250–350 ms ·
page & section entrances 400–600 ms.
**Easing:** `cubic-bezier(0.22, 1, 0.36, 1)` everywhere.

Required primitives:
- `<Reveal>` / `<Stagger>` / `<StaggerItem>` — scroll-triggered entrances
  (opacity + 12–20px translate), `once: true`, stagger 0.05–0.08 s.
- Page transition via `app/template.tsx` (remounts per navigation).
- Hover: max 2px lift, 150–250 ms; press: 1px translate; arrow icons travel 3px.
- Overlays (dialog, sheet, popover, dropdown, tooltip): animate **in and out**.
  Radix Presence detects exit by a change of `animation-name`, so the exit
  **must use a different keyframes name** than the enter.
- Scroll-linked motion only where it communicates progress (reading progress,
  a step connector). Never parallax.
- **Reduced motion:** handle once, globally — `<MotionConfig reducedMotion="user">`
  plus a `prefers-reduced-motion` block in CSS that zeroes animation
  **duration, delay and iteration**, and transition duration/delay. Never branch
  rendered markup on `useReducedMotion()` (it causes hydration mismatches).
- Never animate `width`, `height`, `top`, `left`, `margin`. Animate `opacity`,
  `transform`, and `filter` only.

## ACCESSIBILITY (not optional)

- One `<h1>` per page; headings in order; landmarks (`header`/`main`/`footer`/`nav`).
- Every input has a `<label>`; errors use `aria-invalid` + `aria-describedby`.
- Real `<button>` / `<a>` — never clickable divs.
- Visible `:focus-visible` ring on every interactive element. Never remove
  `outline` without a replacement.
- Icon-only buttons need `aria-label`.
- Decorative images/SVG: `alt=""` / `aria-hidden="true"`.
- Colour contrast ≥ 4.5:1 for body text.
- Standalone text links get a ≥24px pointer target without shifting layout.
- Everything must remain usable with keyboard only and with JS animations
  disabled.

**Phase 6 — Verify.**
